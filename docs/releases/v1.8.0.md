# AE Toolkit v1.8.0

**Release date:** 2026-08-12 · 187 commits since v1.7.0

This release makes AET easier to hand off between sessions and machines, adds mechanical guardrails at review time, hardens the ship/close path, and removes manual bookkeeping around plans and verdicts.

---

## Highlights

- **Context and memory commands** — `aet context`, `aet learnings append`, and `aet handoff` carry state and lessons across runs.
- **Mechanical review lenses** — identity-conflation and boundary-contract lenses catch common regressions at `aet gate submit --stage review`.
- **More reliable shipping** — atomic closure transaction, stacked PR split, squash-merge verification fallback, and branch deletion on close.
- **Multi-machine state sync** — queue state and verdicts travel through `refs/aet/*` so you can move between machines without copying `~/.aet` files.
- **Generated CLI reference** — `aet docs generate` keeps `docs/CLI.md` current and machine-independent.
- **Cleaner plan lifecycle** — live plans are transient working copies and are archived automatically at terminal closure.
- **Atomic stage gates** — `aet state set-stage` and `aet gate submit` update footer and ledger together, removing hand-built verdict JSON.

## What's new

### Context and memory commands

You no longer have to manually paste project state or repeat background in every session.

- **`aet context`** — Generates a structured session-start payload with git state, plan stages, budgets, a digest of current ADR rules, and recent learnings. Use it to prime an agent before a work session.
- **`aet learnings append`** — Records lessons in a validated, append-only JSONL ledger so they become durable inputs for future context.
- **`aet handoff`** — Leaves run-scoped notes that the next agent can read, so context survives across `aet run` sessions without leaking into committed files.

### Mechanical review lenses

`aet gate submit --stage review` now runs two new fail-closed lenses:

- **Identity-conflation lens** — Blocks diffs that accidentally mix identifier namespaces (for example, reusing a user id where a task id is expected).
- **Boundary-contract lens** — Enforces path-level boundary rules and agreement tests, so refactors do not silently violate module contracts.

These are mechanical gates, not replacements for `aet-review`, but they stop the most common classes of regression at submit time.

### More reliable shipping

- **Mechanical closure transaction** — `aet ship close` now updates queue state, ledger events, and plan footer in one atomic git-refs transaction, so a partial failure cannot leave a task half-closed.
- **`aet ship split`** — Resets soft and groups commits when you need to split a stacked PR.
- **`aet ship verify --squash-fallback`** — Verifies a squash merge even when the merge commit hash does not match exactly.
- **`aet ship close --delete-branch`** — Optionally deletes the task branch after closure.

### Multi-machine workflows

Queue state and verdicts now sync via `refs/aet/*` push/fetch across commands (`sprint add`, `state set-stage`, `gate submit`, `ship close`). You can move between machines or share state with teammates without manually copying local `~/.aet` files.

### Generated, machine-independent CLI reference

`aet docs generate` regenerates `docs/CLI.md` from the live Typer command tree. A drift guard in the test suite keeps the reference current and prevents it from embedding one contributor's home directory.

### Cleaner plan lifecycle

- **Live plans are transient** — `docs/plans/*.md` files are gitignored working copies while a task is active.
- **Automatic archival** — When a task reaches `merged` or `abandoned`, its plan is moved to `docs/plans/archive/`.
- **Frontmatter `status` is no longer authoritative** — Settled-ness now derives from queue state, git ancestry, and the terminal footer, eliminating stale `status` drift.

### Atomic stage gates

- **`aet state set-stage`** updates both the queue state and the plan footer in one write.
- **`aet gate submit`** builds verdict payloads automatically from `--from-pytest`, `--summary`, or `--divergence` when you do not pass `--evidence`.

You no longer need to construct JSON verdict files by hand in `aet-qa`, `aet-review`, or `aet-cso`.

## Upgrade notes

1. Update to v1.8.0 and run `aet --version` to confirm the binary is current.
2. No data migration needed — existing queues, plans, and telemetry carry over.
3. If you work across multiple machines, push and fetch `refs/aet/*` as you would any other shared ref.
