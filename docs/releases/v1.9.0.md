# AE Toolkit v1.9.0

**Release date:** 2026-08-15 · 39 commits since v1.8.0

This release hardens multi-machine workflows, makes the task record the source of truth for plan specs, and fixes several long-standing telemetry and orchestrator defects.

---

## Highlights

- **Plan specs travel in the task record** — the full plan (routing, title, body, task list) is embedded in the task record and rendered into the worktree at run start, so a plan authored on one machine reaches another without committing live plan files.
- **git-refs backend is tracked** — `.agents/aet-config.json` now selects `git-refs` by default, so queue state lives in `refs/aet/*` and travels with the repository instead of hiding in a gitignored local file.
- **Sealed tasks stay sealed** — terminal closure pushes explicit ref deletions to origin, preventing completed tasks from resurrecting as live work on other clones.
- **Missing verdict recovery** — when a stage finishes but its verdict file is missing, the orchestrator runs a narrow recovery session instead of discarding and re-running the entire stage.
- **Claude telemetry works** — session-log slugging, piped commands, and the real Claude Code record shape are now handled correctly, so test-run records are extracted from real transcripts.
- **Safer ledger** — the provenance ledger verifies content addresses on load and appends events instead of rewriting the whole file.

---

## What's new

### Portable plan specs

`aet-work` no longer depends on committed plan files to carry a plan across machines. When a task is created from a plan, the spec is stored in the task record; when the orchestrator starts the task, it renders the working plan into the worktree. Live plans remain transient working copies; only the task record and the settled history are durable.

### Tracked git-refs backend

Queue state now lives in tracked git refs by default. This means:

- A fresh clone sees the same board as the machine that created it, with no local configure step.
- Multi-machine handoffs no longer rely on copying `~/.aet` files or gitignored JSON.
- The config and store are anchored to the same repository root, removing a class of mismatch errors.

### Reliable cross-clone closure

Three related fixes make closure behave correctly across machines:

- `aet-state transition` now pushes task refs to origin, so an `in_progress` transition is visible to other clones.
- `backend.save()` and `backend.seal()` both push explicit deletion refspecs for pruned task refs, so a sealed task does not leave a stale ref on origin.
- A bug report and cleanup checklist document how to remove refs already stranded by the previous behavior.

### Missing-verdict recovery

Previously, a missing verdict file caused the orchestrator to discard the entire stage and re-run it. Now the orchestrator spawns one narrow session whose only job is to write the missing verdict. Invalid and fail verdicts are never retried, so the gate remains fail-closed.

### Claude transcript reader fixes

Three independent defects meant the Claude reader had never worked on a real transcript:

- Slug generation now handles `.worktrees/` and dotted usernames.
- Piped commands are resolved to the real runner instead of the trailing `tail` or `head`.
- The reader uses the actual record shape emitted by Claude Code (`message.role` / top-level `type`).

### Ledger integrity

The ledger now:

- Recomputes content addresses on load and refuses corrupted lines.
- Appends events instead of rewriting the file from a possibly-truncated index.
- Propagates read errors rather than reporting an unreadable ledger as empty.

---

## Upgrade notes

1. Update to v1.9.0 and run `aet --version` to confirm the binary is current.
2. If you work across machines, run `git fetch --prune origin` once on each clone to clear any task refs already deleted on origin.
3. No data migration needed — existing queues, plans, and telemetry carry over.
