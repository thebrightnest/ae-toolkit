# AE Toolkit v1.0.0 — First Stable Release

**Release date:** 2026-07-12 · 231 commits since v0.10.0

This is the toolkit's first stable release. The headline change: everything now runs through a **single `aet` command**, and the many separate helper binaries are retired. It also brings a local dashboard for your work, tighter control over what enters the queue, and unattended runs you can actually trust.

---

## Highlights

- **One `aet` command for the whole toolkit** — it installs itself and repairs itself when your setup breaks.
- **A local panel** to browse plans, watch pipeline progress, and review run history.
- **Curated intake** — you decide what enters the work queue instead of everything auto-adding.
- **Trustworthy hands-free runs** — the orchestrator protects its state, demands proof before finishing a task, and cleans up after itself.
- **Pipelines as readable data** — task stages live in a config file you can see and that AET checks for mistakes.

---

## What's new

### One command for everything

AET used to install a collection of separate little programs, and you had to remember which did what. Now a **single `aet` command** handles all of them. It **installs itself** and quietly **repairs itself** if your `PATH` gets messed up — less to remember, fewer things that break.

### A dashboard for your work

A new **local panel** gives you a read-only view of your project:

- Browse all your **plans**
- Watch **each task's progress** through its pipeline
- Review **past runs** and their history

The quickest way to answer "what's the agent been up to?" without digging through files.

### You stay in control of the queue

Syncing plans no longer dumps everything straight into the work queue. New plans are parked as **"ready"** or **"blocked"**, and **you** choose what actually enters. A staging area instead of an open floodgate.

### Unattended runs you can trust

The orchestrator — the part that runs tasks hands-free — got a lot more careful:

- **Won't corrupt its own state** — writes are locked and tamper-protected.
- **Requires proof before calling a task "done"** — no more completing work that didn't happen.
- **Cleans up properly** when a task times out or stops, instead of leaving things hanging.

Walk away from a long run and trust the result.

### Stages you can see and check

The sequence of steps a task moves through (plan → review → QA → ship, …) used to be buried in code. It's now written out in a **readable config file**, and AET **lints it for mistakes** automatically. Easier to understand, easier to change, harder to break.

### More places to keep your tasks

You can now store the task queue **inside git itself**, alongside the existing local-files and GitHub Issues options.

---

## Breaking changes

- **Legacy binaries removed.** The old per-skill executables are gone — everything goes through `aet`. If you have scripts or muscle memory calling the old binary names, point them at `aet` instead.

---

## Upgrade notes

1. Update to v1.0.0 and run `aet install` to set up the unified binary.
2. Replace any direct calls to the old binary names with `aet <subcommand>`.
3. No data migration needed — your existing queue, plans, and telemetry carry over.
