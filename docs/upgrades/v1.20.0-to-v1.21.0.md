# Upgrade: AE Toolkit v1.20.0 to v1.21.0

## Who needs to read this

- Anyone with an AE Toolkit install made by `scripts/install.sh` at v1.20.0 or earlier.
- Anyone whose prompts, scripts, or docs call `/aet-work`, `/aet-upgrade`, or
  `/aet-extract-stack`.
- Anyone whose scripts pass `--dry-run` to `aet ship`, `aet state`, or `aet setup`.

## What changed

### 1. `aet update` updates the CLI and skills in place

v1.21.0 adds `aet update` (also available as `aet setup update`). On an install made
by the installer, it fetches the newest release tag, reinstalls the package, and
relinks skills and the `aet` binary. If any step after the checkout fails, the previous
version is restored.

`aet --version` now prints a notice when a newer release exists, and `aet setup verify`
reports whether the installed version is current. See
[Updating](../../README.md#updating) for the full command reference.

### 2. Three skills were retired (ADR-080)

| Removed skill       | Use instead                                                                                            |
| ------------------- | ------------------------------------------------------------------------------------------------------ |
| `aet-work`          | `aet sprint add <plan>` then `/aet-drive` for a queue; `aet run-one <id>` for a single task            |
| `aet-upgrade`       | `/aet-plan` with an upgrade request; its upgrade planning marks the plan critical so it can be queued  |
| `aet-extract-stack` | No replacement; it was a one-off scaffold job outside the plan → implement → ship pipeline             |

`aet setup skills` now removes links to toolkit skills that no longer exist, so the
retired skills disappear from your agent skills directories the next time skills are
linked.

### 3. `--dry-run` was removed from `aet ship`, `aet state`, and `aet setup`

The flag is gone from `aet ship` and all its subcommands, from `aet state reset`,
`transition`, `set-stage`, and `record-merge`, and from `aet setup link`, `skills`,
and `verify`. These commands now run directly and print what they did. Scripts that
still pass the flag fail with an unknown-option error.

To preview an update, use `aet update --check`. The installer keeps its own `--dry-run`.

## How to upgrade

### Installer-managed install

`aet update` first ships in v1.21.0, so an install at v1.20.0 or earlier has to re-run
the installer once:

```bash
curl -fsSL https://raw.githubusercontent.com/thebrightnest/ae-toolkit/main/scripts/install.sh | bash
```

The installer relinks skills with the new `aet setup skills`, which also removes the
links to the retired skills. From v1.21.0 on, use `aet update`.

### Development checkout

```bash
git pull
make install-skills
```

### `pip` install

```bash
pip install --upgrade git+https://github.com/thebrightnest/ae-toolkit.git@v1.21.0
aet setup skills
```

### Skills installed with `npx skills add`

`npx` does not remove skills that left the repo. Delete the `aet-work`, `aet-upgrade`,
and `aet-extract-stack` directories from your agent skills directory by hand.

## After you upgrade

1. Run `aet setup verify` and confirm it reports the expected version and
   `(up to date)`.
2. Check that your agent skills directory no longer lists `aet-work`, `aet-upgrade`,
   or `aet-extract-stack`.
3. Search your project prompts and scripts for `aet-work`, `aet-upgrade`,
   `aet-extract-stack`, and `--dry-run`, and switch them to the replacements above.
