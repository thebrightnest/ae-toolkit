# Upgrade: AE Toolkit v1.5.0 to v1.6.0

## What changed

The AET project config file was renamed from `.agents/aet-work.json` to
`.agents/aet-config.json`. The old file is no longer read as a fallback; if it
is the only config present, AET commands fail closed and tell you exactly how
to migrate.

Two first-class adoption modes are now documented and reachable through the
CLI:

- **Team mode** — one committed file: `.agents/aet-config.json`.
- **Shadow mode** — one personal file: `~/.aet/{config-slug}/config.json`,
  nothing committed to the repo.

Config resolution is now repo-root-anchored and uses a config-specific slug so
it works identically from any subdirectory or linked worktree.

## Before you upgrade

1. Check whether your project has an AET config file:

   ```bash
   ls .agents/aet-work.json .agents/aet-config.json 2>/dev/null
   ```

2. If neither file exists, you do not need to migrate; skip to
   [First-time setup](#first-time-setup).

## If you have `.agents/aet-work.json`

Run the migration command:

```bash
aet configure --migrate
```

This renames `.agents/aet-work.json` to `.agents/aet-config.json`. If the old
file is tracked in git, the rename uses `git mv` so history is preserved. The
migration refuses to overwrite an existing `.agents/aet-config.json`.

After migrating, verify that config resolves:

```bash
aet setup verify
```

## If you want to switch to shadow mode

To keep AET config out of the repo entirely:

```bash
aet configure --guided --scope shadow --integration-mode pr-per-task
```

Then remove the in-tree file if it exists:

```bash
rm .agents/aet-config.json
```

Verify that nothing AET-related is left in `git status`:

```bash
git status
```

## First-time setup

On a fresh project, run the guided setup:

```bash
aet configure --guided
```

Answer the two questions:

1. **Scope** — `team` writes `.agents/aet-config.json`; `shadow` writes
   `~/.aet/{config-slug}/config.json`.
2. **Integration mode** — `pr-per-task` (default, one PR per plan) or
   `single-pr` (one PR for an epic branch).

## Verify the new commands

```bash
aet setup verify          # shows resolved trunk, integration branch, and mode
aet run --base main       # per-run integration-branch override
aet run-one --base main docs/plans/FEAT-001.md
```

## What to update in your skills

If you have copied skill files into a project, refresh them from the toolkit
repo. In particular, `aet-work` and `aet-ship` no longer hardcode `origin/main`
as the merge target and no longer reference the retired `github` task backend.

## Breaking changes

- `.agents/aet-work.json` is no longer read.
- `configure-backend` is retired; use `aet configure`.
- `task_backend: github` is no longer valid; GitHub Issues mirroring is
  configured on the orthogonal `projections` axis in `.agents/aet-config.json`.
