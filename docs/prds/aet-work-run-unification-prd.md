# PRD: Unify aet-work `run` with OS-Process Isolation

## Overview

The `aet-work` skill currently exposes two AFK loop commands:

- `run` — attempts cooperative context clearing between tasks ("CLEAR CONTEXT — request a new session or context reset")
- `run-scripted` — generates a bash orchestrator that spawns a fresh OS process per task

The cooperative `run` does not work in practice. No mainstream agent runtime (Claude Code, Kimi Code, Cursor, Windsurf, Aider) can clear its session and continue executing skill instructions mid-loop. The instruction is ignored, context degrades, and task quality drops after 3–4 iterations. The `run-scripted` command, added later, solves this with guaranteed process isolation and has been the de-facto way to run the queue.

This PRD replaces the broken `run` with the working `run-scripted` mechanism, keeping the `run` command name and removing `run-scripted` entirely.

## Goals

1. `aet-work run` becomes the single, reliable AFK loop command
2. The new `run` uses the proven OS-process isolation mechanism (formerly `run-scripted`)
3. `run-scripted` is removed from the skill — no backward-compatible alias
4. All references and documentation are updated to describe a single command
5. `make validate` and `make package` pass

## Non-Goals

- No changes to the orchestrator script logic itself (it already works)
- No new runtime detection heuristics
- No new features (dry-run, parallel execution, etc.)
- No changes to `init-queue`, `status`, `next`, or `cleanup`

## User Stories

- As a developer using `aet-work`, I want one obvious command to run the queue so I don't have to choose between a broken and a working option.
- As a maintainer, I want the skill to stop documenting a command that cannot work, so users don't waste time on it.
